# page-check

HTML 파일을 읽고 아래 5가지를 점검한 뒤 심각도별로 보고한다. 수정은 하지 않는다 — 사용자가 고쳐 달라고 하면 그때 고친다.

## 대상

인자로 파일/글롭이 주어지면 그것. 없으면 저장소의 `**/*.html` (단, `node_modules`, `dist`, `build` 제외).

## 점검 항목

| # | 항목 | 판정 | 심각도 |
|---|------|------|--------|
| 1 | `<title>` | `<head>` 안에 비어있지 않은 `<title>` 존재 | 없음 → 🔴 / 비어있거나 무의미("Document") → 🟡 |
| 2 | 깨진 내부 링크 | `href`/`src` 중 상대·루트 경로가 실제 파일로 존재하는지. `#id`는 문서 내 해당 id 존재 여부. `http(s)://`, `mailto:`, `data:`는 건너뜀 | 파일 없음 → 🔴 / 앵커 대상 없음 → 🟡 |
| 3 | 이미지 alt | 모든 `<img>`에 `alt` 속성 존재 | 속성 자체가 없음 → 🔴 / `alt=""`인데 장식용이 아닌 듯 → 🟡 |
| 4 | 모바일 viewport | `<meta name="viewport" content="width=device-width, ...">` | 없음 → 🔴 / 있으나 `user-scalable=no`·`maximum-scale=1` → 🟡(접근성) |
| 5 | 한글 인코딩 | `<meta charset="utf-8">`이 `<head>` 앞부분에 존재 + 파일 실제 바이트가 UTF-8 | 선언 없음/불일치 → 🔴 / BOM 있음 → 🟢 |

## 심각도 기준

- 🔴 **심각** — 사용자에게 실제로 깨져 보이거나(모지바케, 404 이미지), 접근성·SEO가 근본적으로 망가지는 것
- 🟡 **주의** — 동작은 하지만 품질/접근성 문제
- 🟢 **제안** — 있으면 좋은 개선

## 출력 형식

파일별로:

```
## index.html

🔴 심각 (2)
- L5  <title> 없음 — 탭 제목과 검색 결과에 파일명이 그대로 노출됨
- L59 <img>에 alt 없음 — 스크린리더가 이미지를 읽지 못함

🟡 주의 (1)
- L12 <a href="about.html"> — 해당 파일이 저장소에 없음

🟢 제안 (0)
```

문제가 없는 항목은 나열하지 말고 마지막에 한 줄로 `✅ 통과: viewport, 인코딩` 처럼 요약한다. 전부 통과면 `✅ 5개 항목 모두 통과`.
